## 1. 프로젝트 개요
---
### 한 줄 정의
개인화된 만남 일정 추천 웹 서비스

### 제품 목표
사용자의 취향과 만남 목적에 맞춰 번거로움 없는 맞춤형 일정을 제공함으로써, 약속 계획에 드는 시간과 결정 피로도를 획기적으로 줄여 사용자에게 만족스러운 경험을 선사합니다.

### 배경
많은 사람들이 데이트, 지인 모임, 파티 등 다양한 약속을 계획할 때 무엇을 해야 할지, 어떤 장소로 가야 할지 결정하는 데 어려움을 겪습니다. 식당, 놀거리, 가격, 교통편 등 방대한 정보를 일일이 검색하고 조율하는 과정에서 정보 과부하와 결정 피로도를 느끼며, 이러한 문제 해결을 위한 개인화된 솔루션이 부재합니다.

### 사용자 문제
사용자들은 약속 계획 시 방대한 정보 속에서 자신과 일행의 취향 및 예산에 맞는 활동을 찾고, 이동 동선과 시간을 고려하여 효율적인 일정을 구성하는 데 큰 어려움을 겪습니다. 이로 인해 많은 시간과 에너지를 소비하며, 결국 만족스럽지 못한 계획으로 이어지거나 아예 계획을 포기하기도 합니다.

### 해결 방안
사용자의 만남 목적, 인원, 시간, 장소, 선호/비선호 활동 및 음식, 예산 등의 다양한 요구사항을 입력받아, 인공지능 기반으로 최적화된 당일 맞춤형 일정을 생성하여 제공합니다. 초기에 3가지 후보 일정을 제시하고, 사용자 피드백을 반영하여 일정을 반복적으로 수정 및 개선할 수 있는 기능을 통해 만족도를 높입니다. 서비스는 구글 계정으로 로그인하여 이용하며, 일정 생성에 필요한 AI(Claude) API 키는 사용자가 본인 계정으로 발급받아 서비스에 등록하는 방식(BYOK)으로 운영하여, 사용자별 이용량과 비용을 사용자 스스로 관리할 수 있게 합니다.

### 차별점
일반적인 장소 추천이나 수동적인 웹 검색과 달리, 이 서비스는 사용자의 미묘하고 복합적인 요구사항(예: '실내 위주', '특정 음식 제외', '플레이스테이션 가능', '예산 범위 내')을 정확히 반영하여 고도로 개인화된 일정을 제안합니다. 또한, 일방적인 추천이 아닌, 사용자의 피드백을 실시간으로 반영하여 일정을 수정하고 발전시키는 인터랙티브한 경험을 제공합니다.

### 타겟 사용자
주로 20대 후반에서 40대 초반의 직장인 및 대학생으로, 데이트, 친구 모임, 동성 지인 모임 등 다양한 약속을 자주 계획하지만, 방대한 정보와 취향 조율의 어려움으로 인해 시간 소모와 스트레스를 느끼는 '결정하기 어려운 개인'들입니다. 특히, 서울 및 경기 등 수도권에 거주하며 새로운 경험과 효율적인 시간 관리를 중시하는 사용자층을 주요 타겟으로 합니다.

### 사용자 시나리오
김민준 씨(32세, 직장인)는 여자친구와 함께 무더운 여름 주말에 오전 10시부터 저녁 9시까지 서울 강남 지역에서 데이트를 계획하고 싶어 합니다. 푹푹 찌는 날씨 때문에 실내 위주의 활동을 선호하며, 저녁 메뉴로는 파스타나 스테이크를 먹고 싶지만 해산물은 싫어합니다. 활동적인 것을 좋아해 보드게임 카페나 VR 체험을 고려하고 있지만, 전체 예산은 1인당 5만 원을 넘지 않았으면 좋겠습니다. 민준 씨는 이 서비스를 통해 이러한 복합적인 요구사항을 반영한 데이트 일정을 3가지 후보로 추천받고, 그중 하나를 선택하여 세부 활동을 수정하는 과정을 거쳐 완벽한 데이트 계획을 완성합니다.

### 핵심 지표
사용자 만족도(별점 평점 4.0 이상), 일정 전환율(제공된 일정 중 1개 이상 선택 및 수정 비율 30% 이상), 사용자 유지율(재방문율 20% 이상)

### 리스크
AI 추천의 낮은 정확도로 인한 사용자 불만족, 다양한 지역 업체 및 실시간 데이터(영업시간, 재고, 가격 변동 등) 통합의 어려움, 초기 데이터 확보의 어려움, 복잡한 사용자 입력 과정으로 인한 이탈률 증가, LLM 기술의 한계로 인한 예상치 못한 결과 도출. 사용자가 직접 AI API 키를 발급·등록해야 하는 BYOK 구조로 인한 온보딩 진입장벽 및 이탈 증가, API 키 저장 방식에 대한 보안 신뢰 확보 필요.

## 1. 개인화된 일정 생성
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 작성중

사용자의 만남 목적, 인원, 시간, 장소, 선호·비선호 활동 및 음식, 예산 등 입력된 정보를 기반으로 개인화된 당일 일정을 3가지 후보로 생성하여 제공합니다. 일정에는 예상 시작·종료 시간, 활동 및 장소 정보, 활동별 1인당 예상 비용, 구간별 이동 동선·이동시간·교통비를 포함합니다. 이동시간과 교통비는 네이버 지도에서 제공하는 대중교통 또는 도보 경로 정보를 바탕으로 계산하며, 식사·체험·입장 등의 활동 비용은 장소 가격대를 바탕으로 한 1인당 참고 범위로 표시합니다. 조건을 만족하는 장소가 없거나 예산·시간·정보 조건으로 일정 생성이 어려우면, 그 이유와 조정이 필요한 조건을 안내하고 사용자가 조건을 완화해 다시 추천받을 수 있게 합니다.

**수용 기준:**
```
1. ○ 사용자가 필수 및 선택 정보를 입력했을 때, 시스템은 3가지의 차별화된 일정 후보를 제시해야 한다.
2. ○ 각 일정은 예상 시작·종료 시간, 활동 및 장소 정보, 활동별 1인당 예상 비용, 구간별 이동 동선·이동시간·교통비를 포함해야 한다.
3. ○ 이동시간과 교통비는 네이버 지도에서 제공하는 대중교통 또는 도보 경로 정보를 기준으로 계산해야 한다.
4. ○ 식사·체험·입장 활동의 예상 비용은 장소 가격대를 바탕으로 한 1인당 참고 범위임을 표시해야 한다.
5. ○ 조건을 만족하는 장소가 없거나 예산·시간·정보 조건으로 일정을 만들기 어려운 경우, 원인과 조정 가능한 조건을 안내하고 사용자가 조건을 완화해 다시 추천받을 수 있어야 한다.
6. ○ 사용자가 AI API 키를 등록하지 않은 상태에서 일정 추천을 요청하면, 일정 생성 대신 API 키 등록이 필요함을 안내하고 등록 화면으로 이동할 수 있어야 한다.
```

## 2. 반복적 일정 수정 및 피드백
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 작성중

사용자는 제시된 3가지 일정 후보 중 하나를 선택한 후, 해당 일정에 대한 피드백(예: 활동 변경, 시간 조정, 예산 증액)을 입력하여 일정을 수정하거나 새로운 일정 후보를 요청할 수 있습니다. 수정 요청을 반영할 수 없으면 시스템은 충족하기 어려운 조건과 그 이유를 안내하고, 예산·시간·지역·선호 조건 중 조정 가능한 항목을 제안합니다. 사용자는 제안된 조건을 선택하거나 직접 변경한 뒤 다시 일정을 요청할 수 있습니다.

**수용 기준:**
```
1. ○ 사용자는 제시된 3가지 일정 중 하나를 선택할 수 있어야 한다.
2. ○ 선택된 일정에 대해 사용자가 텍스트 또는 옵션 선택 방식으로 수정 요청 피드백을 제공할 수 있어야 한다.
3. ○ 피드백에 따라 시스템은 기존 일정을 수정하여 재제시하거나, 피드백을 반영한 새로운 일정 후보를 생성하여 제시해야 한다.
4. ○ 사용자는 마음에 드는 후보가 없을 경우, 추가적인 3가지 일정 후보를 요청할 수 있어야 한다.
5. ○ 수정 요청을 반영할 수 없는 경우, 시스템은 그 이유와 조정 가능한 예산·시간·지역·선호 조건을 안내하고 사용자가 조건을 바꿔 다시 요청할 수 있게 해야 한다.
```

## 3. 단계별 정보 입력 인터페이스
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 작성중

사용자가 복잡한 일정을 쉽고 직관적으로 입력할 수 있도록 단계별 질문 형식의 인터페이스를 제공하며, 필수 정보와 선택 정보가 명확히 구분되어야 합니다.

**수용 기준:**
```
1. ○ 서비스 최초 이용 시 사용자에게 순차적으로 질문을 제시하여 필요한 정보를 수집해야 한다.
2. ○ 시간 선택(시작/종료), 인원수, 만남 목적(데이트/친구 등), 장소(지역), 선호/비선호 활동 및 음식, 예산 등 주요 입력 필드를 제공해야 한다.
3. ○ 필수 입력 항목과 선택 입력 항목이 명확하게 구분되어야 하며, 선택 항목은 비워둘 수 있어야 한다.
4. ○ 사용자 입력 중간에 '건너뛰기' 옵션 또는 입력된 정보에 대한 요약 확인 기능을 제공해야 한다.
```

## 4. 상세 활동 및 장소 정보 제공
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 작성중

생성된 일정에 포함된 식당, 카페, 놀거리 등 각 장소의 이름, 주소, 운영 시간, 연락처, 가격대와 간략한 소개를 제공합니다. 식사·체험·입장 등의 가격은 정기적으로 갱신된 장소 가격대를 바탕으로 한 1인당 대략적인 참고 범위로 표시하며, 참여 인원 전체의 합산 금액, 실제 결제 금액, 실시간 가격·재고·좌석 정보는 제공하지 않습니다. 일정의 각 장소 사이에는 네이버 지도 경로 정보에 따른 도보 또는 대중교통 이동시간과 교통비를 표시하고, 정보가 누락되었거나 최신 여부를 확인하기 어려운 경우에는 확인이 필요함을 안내합니다.

**수용 기준:**
```
1. ○ 일정 내 모든 활동 및 장소에 이름, 주소, 운영 시간, 연락처 정보를 제공해야 한다.
2. ○ 각 장소의 식사·체험·입장 비용은 참여 인원 합산이 아닌 1인당 대략적인 가격대 또는 참고 범위로 표시해야 한다.
3. ○ 장소 사이의 이동 구간에는 네이버 지도 경로 정보에 따른 이동수단, 이동시간, 교통비를 표시해야 한다.
4. ○ 가격대 또는 경로 정보가 누락되었거나 최신 여부를 확인하기 어려운 경우, 사용자에게 확인 필요와 일정 조건에 미칠 수 있는 영향을 표시해야 한다.
5. ○ 실시간 장소 가격, 재고, 좌석 정보는 제공하지 않아야 한다.
```

## 5. 일정 공유 기능
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 작성중

사용자는 생성하거나 수정 완료한 일정을 지인에게 공유 가능한 웹 링크로 전달할 수 있습니다. 공유 링크는 네이버 지도의 길찾기 결과처럼 링크를 받은 사람이 로그인 없이 열람하는 공개 공유 방식으로 제공하며, 일정의 활동·장소·시간·동선·예상 비용을 표시합니다. 사용자 계정 정보, 입력 원문, 피드백 대화 등 일정 열람에 필요하지 않은 개인 정보는 공유 화면에서 제외합니다.

**수용 기준:**
```
1. ○ 사용자는 완성된 일정을 공유 가능한 웹 링크로 생성할 수 있어야 한다.
2. ○ 공유 링크를 받은 사람은 로그인 없이 일정의 활동, 장소, 시간, 동선, 예상 비용을 확인할 수 있어야 한다.
3. ○ 공유 화면에는 사용자 계정 정보, 원본 입력 내용, 일정 수정 피드백 등 일정 열람에 필요하지 않은 개인 정보를 표시하지 않아야 한다.
4. ○ 일정 내용을 이미지 파일(예: JPG, PNG) 또는 PDF 형태로 저장하거나 내려받을 수 있어야 한다.
```

## 6. 지역별 최신 데이터 연동
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 작성중

정확하고 실용적인 일정 추천을 위해 서울·경기 등 국내 주요 도시의 음식점, 카페, 문화시설, 놀거리 기본 정보를 수집하고 정기적으로 갱신합니다. 제공 범위는 장소 이름, 주소, 카테고리, 운영 시간, 가격대와 네이버 지도에서 제공하는 도보·대중교통 경로의 이동시간 및 교통비로 한정합니다. 장소의 실시간 재고·좌석·가격 변동은 포함하지 않으며, 가격대·운영 시간 또는 경로 정보의 확인 시점이 오래되었거나 누락된 경우 최신 정보 확인이 필요함을 표시하고 추천 조건 충족에 미치는 영향을 안내합니다.

**수용 기준:**
```
1. ○ 서울·경기 등 국내 주요 도시의 음식점, 카페, 문화시설, 놀거리 장소 정보를 제공해야 한다.
2. ○ 각 장소에 이름, 주소, 카테고리, 운영 시간, 가격대를 제공해야 한다.
3. ○ 장소 간 도보·대중교통 이동시간과 교통비는 네이버 지도에서 제공하는 경로 정보를 기준으로 제공해야 한다.
4. ○ 장소 정보와 경로 정보가 누락되었거나 확인 시점이 오래된 경우 최신 정보 확인이 필요함을 표시해야 한다.
5. ○ 실시간 재고, 좌석, 장소 가격 변동은 제공 범위에서 제외해야 한다.
```

## 7. 구글 로그인
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 작성중

사용자는 구글 계정으로 로그인하여 서비스를 이용합니다. 별도의 회원가입 절차 없이 구글 인증만으로 계정을 생성하며, 로그인해야만 일정 생성·수정·확정 등 핵심 기능을 이용할 수 있습니다. 로그인 없이도 공유 링크를 통한 일정 열람은 가능합니다.

**수용 기준:**
```
1. ○ 사용자는 구글 계정으로 로그인 버튼을 클릭해 구글 인증 절차를 거쳐 서비스에 로그인할 수 있어야 한다.
2. ○ 최초 로그인 시 별도 가입 절차 없이 구글 계정 정보(이메일, 이름, 프로필 이미지)로 자동으로 계정이 생성되어야 한다.
3. ○ 인증에 실패한 경우, 실패 사실을 안내하고 다시 시도할 수 있어야 한다.
4. ○ 로그인하지 않은 사용자는 일정 생성·수정·확정·공유 링크 생성 기능에 접근할 수 없으며, 로그인 화면으로 안내되어야 한다.
5. ○ 로그인하지 않은 사용자도 이미 발급된 공유 링크로 일정을 열람할 수 있어야 한다.
```

## 8. AI API 키 등록·관리
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 작성중

사용자는 로그인 후 설정 화면에서 AI 제공자(Claude 또는 GPT)를 선택하고, 본인이 발급받은 해당 제공자의 API 키를 등록하여 일정 추천 기능을 이용합니다. 등록된 키는 안전하게 암호화되어 저장되며, 원문은 어떤 화면에도 다시 노출되지 않고 마스킹된 형태로만 표시됩니다. 사용자는 등록된 제공자·키를 언제든 변경하거나 삭제할 수 있습니다.

**수용 기준:**
```
1. ○ 사용자는 API 키를 등록하기 전 AI 제공자(Claude 또는 GPT)를 선택할 수 있어야 한다.
2. ○ 사용자는 설정 화면에서 선택한 제공자의 API 키를 입력하여 등록할 수 있어야 한다.
3. ○ 등록 시 시스템은 선택한 제공자 기준으로 키의 유효성을 확인한 후 저장해야 하며, 유효하지 않은 키는 등록되지 않고 사유를 안내해야 한다.
4. ○ 저장된 API 키는 암호화되어 저장되어야 하며, 등록 이후에는 마스킹된 형태로만 화면에 표시되어야 한다.
5. ○ 사용자는 등록된 제공자와 API 키를 변경하거나 삭제할 수 있어야 한다. 제공자를 변경하면 기존 키는 삭제되고 새로 등록해야 한다.
6. ○ API 키가 등록되지 않은 상태에서는 일정 생성 기능을 이용할 수 없으며, 등록 화면으로 안내되어야 한다.
```

## 9. 전역 고정 로고·홈 이동
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 작성중

로그인 여부와 관계없이 모든 화면 상단에 서비스 로고("모두약속")가 고정으로 노출됩니다. 로고를 클릭하면 현재 어떤 화면에 있든, 입력 중인 내용과 관계없이 즉시 홈 화면으로 이동합니다. 화면별 개별 뒤로가기 버튼과는 별개로 항상 존재하는 전역 네비게이션 요소입니다.

**수용 기준:**
```
1. ○ 로고는 로그인 화면, 공개 공유 화면을 포함한 모든 화면 상단에 항상 노출되어야 한다.
2. ○ 로고는 스크롤과 무관하게 화면에 고정되어야 한다.
3. ○ 로고를 클릭하면 예외 없이 홈 화면으로 이동해야 한다.
4. ○ 화면 콘텐츠는 로고 영역과 겹치지 않아야 한다.
```
