## 1. 방향성
- 복잡한 코드가 아닌, 단순하고 흐름을 파악할 수 있는 코드를 작성한다.
- 언어별 네이밍 규칙(카멜/스네이크)과 프로젝트 내 개발 표준을 준수한다.
- 적절한 주석을 통해 제3자가 보더라도 유지보수가 가능해야 한다.

## 2. 네이밍 규칙
| 영역 | 규칙 | 예시 |
|---|---|---|
| Python (FastAPI) | 변수/함수: snake_case, 클래스: PascalCase | `normalize_conditions`, `ScheduleResponse` |
| Vue/JS/TS | 변수/함수: camelCase, 컴포넌트 파일: PascalCase | `fetchSchedule`, `ScheduleCard.vue` |
| DB 테이블/컬럼 | snake_case | `schedule_session`, `user_id` |

## 3. 파일 헤더 주석 규칙 (필수)
**모든 신규 소스 파일(백엔드 `.py`, 프론트 `.vue`/`.ts`) 최상단에 아래 헤더를 기입한다.**

### Python
```python
# ------------------------------------------------------------------
# 작성자      :
# 작성목적    :
# 작성일      : YYYY-MM-DD
# 변경사항 내역 (날짜, 변경목적, 변경내용 순으로 기입)
#
# ------------------------------------------------------------------
```

### Vue / TS
```ts
/**
 * ------------------------------------------------------------------
 * 작성자      :
 * 작성목적    :
 * 작성일      : YYYY-MM-DD
 * 변경사항 내역 (날짜, 변경목적, 변경내용 순으로 기입)
 *
 * ------------------------------------------------------------------
 */
```

- 파일을 새로 만들 때 위 템플릿을 그대로 붙여넣고 작성자/목적/일자를 채운다.
- 파일을 수정할 때는 "변경사항 내역"에 한 줄 추가한다: `# 2026-08-10, 예산 검증 로직 수정, budget 필드 nullable 허용`
- 설정 파일(`.env`, `package.json` 등)과 자동 생성 파일에는 적용하지 않는다.

## 4. 일반 주석 규칙
- 코드가 "무엇을" 하는지는 이름으로 설명하고, 주석은 "왜" 그렇게 했는지(숨은 제약, 임시방편, 특이 케이스)만 남긴다.
- 지운다고 오해가 생기지 않는 주석은 쓰지 않는다.

## 5. 스킵한 것 → 필요해지면 추가
- 자동 린트로 헤더 누락 검사 (pre-commit hook 등) → 팀원 늘어나서 수기 체크가 안 될 때
